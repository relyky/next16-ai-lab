# 散佈圖的三個維度靠軸標題、刻度單位與圖例標示，不靠 Tooltip

散佈圖有三個維度：X 軸、Y 軸，以及選填的氣泡大小。在此之前，這三者在**靜態畫面上全部無標示**——兩個軸都是裸數字，氣泡大小沒有任何說明，單一數列時連圖例都不顯示。名稱只透過 `name` prop 掛給 Tooltip，滑鼠移上去才看得到。

但 AI 對話產生的圖表最常見的使用方式是**截圖轉貼**，Tooltip 在那個情境下完全失效。讀者拿到的是一張讀不出「哪個軸是什麼」的圖。

改為把資訊拆進**刻度**與**圖例**兩處，比照 recharts 官方 [`SimpleScatterChart`](https://recharts.github.io/en-US/examples/SimpleScatterChart/)：schema 新增六個選填的頂層欄位：`xLabel` / `yLabel`（軸的名稱）、`xUnit` / `yUnit`（軸的單位）、`sizeLabel` / `sizeUnit`（氣泡維度的名稱與單位）。單位接在刻度上（`45元`、`1.2M件`），同時解決了「這是什麼」與「數量級多大」兩件事。我們原本照搬了官方模式的一半（`name` + Tooltip）卻沒有另一半（`unit`），資訊量因此比官方範例還少。

## Y 軸單位採頂層 `yUnit`，而非 `series[].unit`

顏色掛在 `series[]` 上（ADR 0003 的「每組數列一色」），單位看似該比照辦理。但**Y 軸刻度只能顯示一種單位**：把單位掛在數列上，schema 就允許「多數列各自宣稱不同單位」這種畫不出來的組合，而型別上完全合法。這與 ADR 0001「型別不該說謊」是同一條理由。

三個單位因此都是頂層欄位，`series` 維持現狀不變。

## 散佈圖一律顯示圖例，與其他圖表刻意分歧

折線／長條／區域／雷達圖的規則是「單一數列時不顯示圖例」，理由是「標題已說明畫的是什麼」。散佈圖取消這條規則，一律顯示。

那個理由**對散佈圖不成立**：折線圖的 X 軸把類別名稱（1月、2月）寫在刻度上，單一數列時 Y 軸語意由 X 軸的脈絡撐住；散佈圖兩軸都是裸數字，沒有任何脈絡可倚靠。**單一數列正是最需要圖例的情境。**

這不是破例——餅圖的 `Legend` 早已無條件顯示。「單一數列不顯示圖例」本來就只是笛卡兒圖與雷達圖的規則，不是全域規則。既有折線／長條／區域／雷達圖不動，並以測試保護該行為不被這次改動波及。

## 氣泡大小自成一個圖例項，圖示為中性空心圓

氣泡大小是三個維度中**唯一沒有軸刻度可依附**的——它沒有軸，圖例是它唯一的靜態標示管道。`sizeKey` 提供時，圖例區在各數列之後追加一項「大小：{sizeLabel ?? sizeKey}」。

該項的圖示刻意是**中性空心圓**，而非數列那樣的實心色圓：這一項表達的是「大小」而非「顏色」，兩者在視覺上必須區分得開，否則讀者會把它讀成第四組數列。

`sizeLabel` 未提供時回退 `sizeKey`，與 `series[].label`「未提供時使用 key」的現行模式完全一致，不是新發明。

官方範例雖有 `ZAxis` 的 `name` / `unit`，但它的 `range` 是固定值、所有點一樣大，**沒有「氣泡大小承載維度」這件事要標示**，故此項無官方前例可循，是我們獨有的需求。

## 圖例 payload 自行組出，而非讓 recharts 收集

recharts 預設從各 `Scatter` 收集圖例項目。追加的「大小」項不對應任何一個 `Scatter`，沒有地方掛得上去，故改以 `Legend` 的 `content` 注入自組的 payload（recharts 3 已移除 `Legend` 的 `payload` prop）。

自行組同時讓數列項與大小項的順序明確可控，而不是依賴 recharts 的收集順序。組出 payload 的規則抽為具名純函式 `scatterLegendPayload` 並單獨測試——項目的組成與順序不必渲染整張圖就能驗。

## 被否決的替代方案

**加一行「圖表解讀」說明文字**（如「X軸：產品售價（元）｜Y軸：…」）。官方模式證明不需要——資訊拆進刻度與圖例即可。多一行文字反而要處理排版一致性，且那行文字無法用於刻度，量級資訊仍然缺席。

**不加軸標題，只靠單位。** 這是本文件初版的立場，現已推翻——見下節。

## 軸標題：先前判定「做不到」，其實是誤判

`xLabel` / `yLabel` 兩個欄位把軸的名稱畫在軸旁邊：X 軸在刻度下方，Y 軸旋轉 -90° 在刻度左側。這是笛卡兒圖最通用的慣例，也是一般人對「軸標題」的預期。

此前兩度判定這件事做不到（commit `f23c4d5`，以及本文件初版的「不做的事」），理由是「recharts 的 `Label` 依水平可用寬度自動斷詞，旋轉後中文被折成一字一行，與函式庫對抗不划算」。

**那個歸因是錯的。斷行與旋轉無關。** `Label` 會把它算出的 viewBox 寬度往下傳給 `Text`，而 `Text` 只在**收到 `width` 時**才斷行：

```js
// recharts/es6/component/Text.js
if ((width || scaleToFit) && !Global.isSsr) { /* 斷行 */ }
```

Y 軸的 viewBox 寬度就是那條窄軸本身的寬度（數十 px），中文因此一字一行。症結是這個**繼承來的寬度**，不是旋轉角度。明確傳 `width: undefined` 即關閉斷行，中文保持一行——實機驗證過，「每月實際銷售數量」這種長標題也不斷行。

教訓值得記下：把一個可設定的參數誤判成函式庫的固有行為，代價是兩次放棄一個使用者一眼就會期待的功能。

### 標題以 `label` 的物件形式傳入，而非 `<Label>` 元素

兩者看似等價，但傳元素會讓 recharts 走「先量測標題再決定軸尺寸」的分支（`XAxis.js` 的 `isValidElement(label)`），該分支在 jsdom 下量到 0 而整個不渲染。物件形式由 recharts 自行建構 `Label`，兩種環境行為一致。

### 垂直順序：刻度 → X 軸標題 → 圖例

X 軸標題用 `insideBottom` 排在軸自己的高度內（再以 `dy` 推離刻度），而非 `bottom`。`bottom` 會把標題排進圖例佔用的帶狀區域，兩者直接疊在一起——實機驗過，不是推測。軸高度因此明給 `X_AXIS_HEIGHT_WITH_LABEL`：`height="auto"` 只在標題是 React 元素時才量測，物件形式量不到。

### 圖例圖示畫在 32 單位的座標空間

recharts 圖例 svg 的 viewBox 是 `0 0 32 32`，顯示寬度才是 14px。`legendIcon` 的內容畫在 **viewBox 座標**裡，照 14 去畫會讓圖示只有四成大小且偏左——實機看起來像一個辨識不出形狀的小點。

## 影響

**六個欄位皆選填，未提供時不出現在圖表定義 JSON 裡。** 圖表定義保持稀疏，與 `stacked`、`colorKey` 等既有選填欄位的處理一致。未提供單位時刻度維持純數字。

**選填欄位的語意必須寫進 tool 描述。** 依 ADR 0003：選填欄位的說明只存在於巢狀 JSON Schema 的 property description 裡，LLM 未必讀得到。散佈圖的 tool 描述因此明文要求「務必傳 `xLabel` 與 `yLabel` 為兩軸命名」、「資料有單位時另傳 `xUnit` 與 `yUnit`」——若 LLM 從不主動使用，這次改動等於沒做。

**`sizeLabel` / `sizeUnit` 沒有 `sizeKey` 時回報錯誤**，與 `range` 的既有處理一致：三者都只描述氣泡這個維度，沒有 `sizeKey` 就沒有維度可描述。靜默忽略會讓 LLM 以為自己成功標了名稱。

**單位與大數值縮寫是兩條獨立路徑。** `tickFormatter`（我們的 K/M/B 縮寫）與 `unit`（recharts 附加）各自運作，recharts 把後者接在前者的輸出之後。疊加後的實際輸出（`1.2M件`）有測試守著——兩條路徑各自正確不保證疊起來正確。

## 後續修正：圖例移進繪圖區左上角（issue #72、#73）

**本文件以上的內容一字未改**——追加而非改寫，與 ADR 0005 同一慣例。

散佈圖的圖例已改用 `position="insideTopLeft"` + `layout="vertical"`，取代已棄用的 `verticalAlign` / `align`。圖例因此排進繪圖區內部的左上角，不再佔用 X 軸下方的帶狀區域。

**受影響的是〈垂直順序：刻度 → X 軸標題 → 圖例〉一節的前提。** 該節記錄「`bottom` 會把標題排進圖例佔用的帶狀區域」——那條帶狀區域現在沒有了。但**結論不變**：X 軸標題仍用 `insideBottom` + `dy`，`X_AXIS_HEIGHT_WITH_LABEL` 仍明給數字。理由從「閃避圖例」變成「標題要留在軸自己的高度內才不被 SVG 下緣裁掉」。同時，舊版為閃避標題而加在圖例上的 `wrapperStyle={{ paddingTop: 12 }}` 微調已不必要，一併移除。

**其餘各節不受影響**：一律顯示圖例、氣泡大小自成一項、圖示畫在 32 單位座標空間、payload 自行組出——這些都與圖例擺在哪裡無關。

**新的已知風險：圖例可能遮住左上角的資料點。** 採用此位置時即知道的取捨。issue #73 以瀏覽器實測複核，兩張樣板圖（8 點與 10 點）皆為 **0 個資料點被遮**，但多數列那張的最高點與圖例色塊僅差數 px。目前的資料閃過了，這個位置對「左上角有資料點」的資料集仍屬脆弱，留待實際案例出現時再處理。
