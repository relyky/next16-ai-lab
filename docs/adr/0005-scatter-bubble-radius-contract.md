# 散佈圖的氣泡大小契約收半徑而非面積

散佈圖的 `sizeKey` 把第三個維度映射到 recharts 的 `ZAxis`，而 `ZAxis.range` 的單位是**面積**——recharts 內部以 `radius = sqrt(size / π)` 反推半徑。我們的 tool 契約不沿用這個單位，改收 `[最小半徑, 最大半徑]`（單位 px），由前端一個具名純函式 `bubbleAreaRange` 換算成面積後才交給 recharts。

面積在**感知上**是正確的選擇——人眼比較圓的大小時比較的是面積，不是半徑；照半徑線性映射會讓大值看起來被過度放大。這個結論我們並不推翻，recharts 用面積是對的。問題出在**數字對呼叫端的可讀性**：`[64, 400]` 換算成半徑是 4.5px 到 11.3px，光看那兩個數字，沒有人猜得出畫出來的點會是多大。LLM 要嘛不敢動這個參數，要嘛傳一個量級完全錯誤的值。

契約收半徑，LLM 拿到的是它直覺會用對的單位（「這張圖的點最大 20px」是可以直接想像的），而易錯的平方與圓周率換算被鎖在前端一個具名、單獨測試過的純函式裡——只有一處會錯，而且那一處有測試守著。

## 被否決的替代方案

**前端寫死一組常數，完全不開放 `range`。** 它更 MVP：schema 少一個欄位、少三條驗證、tool 描述也短一截。

否決的理由是**合適的氣泡範圍與資料的離散程度有關**。點密集時需要小氣泡，否則整張圖糊成一片；點稀疏時可以放大，否則畫面空曠、第三個維度的差異看不出來。寫死一組常數必然會讓其中一種資料集畫出難讀的圖，而那正是散佈圖最有價值的使用情境。開放 `range` 加上前端預設能同時滿足兩者：LLM 不管時有合理的預設，需要調整時調得動。

**另一個被否決的方案是讓 LLM 直接傳 recharts 的面積值。** 它最省事——前端連換算函式都不必寫，參數原樣往下傳。但那等於把 recharts 的內部實作細節洩漏成我們的對外契約：換掉圖表函式庫時契約就得跟著改，而已經產生的圖表定義會全部失效。更直接的代價是上一節說的可讀性——把一個反直覺的單位交給呼叫端，換得前端少寫五行。

## 上限與預設值的由來

**最大半徑上限 40。** 圖表容器高度固定，繪圖區約 180–200px；半徑 40（直徑 80px）約佔四成，仍留得下其他點的空間。這與既有的資料列數上限 100、數列數上限 6 是同一種東西——不是技術限制，而是避免 LLM 產生過大的值拖垮圖表可讀性。

**預設 `[4, 12]`。** 換算後的面積約 `[50, 452]`，與 recharts 自身的預設同一量級。未提供 `range` 時套用此值，畫出來的圖與不特別設定 `ZAxis` 的 recharts 散佈圖看起來相當。

**檢查 `range[0] < range[1]`。** 傳反了會畫出「大值畫小、小值畫大」——一張看起來完全正常但語意完全相反的圖。這種錯誤沒有任何視覺跡象可供察覺，只能在驗證階段擋下。

## `range` 選填而非必填

`sizeKey` 本身已是選填。若 `range` 必填，會出現「有 `range` 沒 `sizeKey`」這種無意義的必填組合——呼叫端被迫為一個自己沒打算用的功能傳參數。兩者都選填，加上前端預設，是唯一不產生無意義組合的設計。

## 有 `range` 無 `sizeKey` 回報錯誤，而非靜默忽略

傳了 `range` 卻沒傳 `sizeKey` 時，`range` 沒有可映射的欄位。此時回報錯誤，與既有 schema 對未知欄位「明確拒絕而非靜默忽略後畫出一張參數對不上的圖」的立場一致（見 ADR 0001 之後各圖採 `strictObject` 的理由）。

靜默忽略在這裡格外有害：LLM 會以為自己成功調整了氣泡大小，而畫面上所有點一樣大。它拿不到任何訊號，也就不會重試。

## 影響

**契約的單位語意難以逆轉。** 改成面積會讓所有既有的圖表定義失效——同一組數字在兩種單位下相差一個平方與 π。這正是它值得記錄的原因：未來讀者看到 `bubbleAreaRange` 時第一個問題會是「為什麼不直接讓 LLM 傳 recharts 的 `range`？」，本文件就是那個問題的答案。

**換算函式必須單獨測試。** jsdom 不產生 SVG 幾何，平方與圓周率兩個易錯點在渲染斷言中驗不到。故 `bubbleAreaRange` 匯出為純函式並自帶測試，涵蓋預設值與自訂值。

**`sizeKey` 與 `range` 的用法必須寫進 tool 的描述。** 選填欄位的說明只存在於巢狀 JSON Schema 的 property description 裡，LLM 未必讀得到——ADR 0003 已記錄這個問題。氣泡大小是散佈圖相對於其他圖表最有價值的部分，若 LLM 從不主動使用，等於沒做。
