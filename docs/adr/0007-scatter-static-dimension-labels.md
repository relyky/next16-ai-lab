# 散佈圖的三個維度靠軸標題與刻度單位標示，不靠 Tooltip

> 取代 ADR 0005、0006——那兩份的主要決策都已被後續改動推翻，此處只留仍守著
> 現行程式碼的部分（氣泡幾何已收斂為前端固定值，不再是契約的一部分），完整
> 推導在 git 歷史裡。

散佈圖有三個維度：X 軸、Y 軸，以及選填的氣泡大小（`sizeKey`）。本文記錄這三者在
**靜態畫面**上如何標示。

AI 對話產生的圖表最常見的用法是**截圖轉貼**，Tooltip 在那個情境下完全失效。
在此之前散佈圖的兩個軸都是裸數字，名稱只掛給 Tooltip，讀者拿到的是一張讀不出
「哪個軸是什麼」的圖。

比照 recharts 官方 [`SimpleScatterChart`](https://recharts.github.io/en-US/examples/SimpleScatterChart/)
把資訊拆進**刻度**與**圖例**兩處。schema 新增六個選填的頂層欄位：

| 欄位 | 回答的問題 | 呈現位置 |
|---|---|---|
| `xLabel` / `yLabel` | 這個軸是什麼 | 軸旁的標題 |
| `xUnit` / `yUnit` | 數量級多大 | 接在刻度後（`45元`、`1.2M件`） |
| `sizeLabel` / `sizeUnit` | 氣泡承載什麼 | Tooltip（無軸可依附） |

單位無法承載「產品售價」這種完整名稱，標題無法回答數量級——兩者是兩件事，不是
二選一。六個欄位皆選填，未提供時不出現在圖表定義 JSON 裡，與 `stacked`、`colorKey`
等既有選填欄位一致。

### 三個單位都是頂層欄位，而非 `series[].unit`

顏色掛在 `series[]` 上（ADR 0003 的「每組數列一色」），單位看似該比照辦理。但
**Y 軸刻度只能顯示一種單位**：掛在數列上，schema 就允許「多數列各自宣稱不同單位」
這種畫不出來卻型別合法的組合。這與 ADR 0001「型別不該說謊」是同一條理由。

### `sizeLabel` / `sizeUnit` 沒有 `sizeKey` 時回報錯誤

兩者都只描述氣泡這個維度，沒有 `sizeKey` 就沒有維度可描述。回報錯誤而非靜默忽略，
與既有 schema 對未知欄位的立場一致（ADR 0001 之後各圖採 `strictObject` 的理由）。
靜默忽略會讓 LLM 以為自己成功標了名稱。

## 散佈圖一律顯示圖例，與其他圖表刻意分歧

折線／長條／區域／雷達圖的規則是「單一數列時不顯示圖例」，理由是「標題已說明畫的
是什麼」。**那個理由對散佈圖不成立**：折線圖的 X 軸把類別名稱（1月、2月）寫在刻度
上，單一數列時 Y 軸語意由 X 軸的脈絡撐住；散佈圖兩軸都是裸數字，沒有脈絡可倚靠。
單一數列正是最需要圖例的情境。

這不是破例——餅圖的 `Legend` 早已無條件顯示。「單一數列不顯示圖例」本來就只是
笛卡兒圖與雷達圖的規則，不是全域規則。既有各圖不動，並以測試保護不被波及。

圖例以 `position` + `layout` 排進繪圖區（取代已棄用的 `verticalAlign` / `align`）。

### 圖例 payload 自行組出，而非讓 recharts 收集

recharts 從各 `Scatter` 原生收集出來的圖例是**反序**的（實測三數列 甲乙丙 → 丙乙甲），
與 `series` 的宣告順序、以及配色對照表的取色順序都對不上——讀者會把圖例的第一項
對到畫面上的另一個顏色。自組 payload 讓圖例順序與 `series` 一致。

規則抽為具名純函式 `scatterLegendPayload` 並單獨測試：項目的組成與順序不必渲染
整張圖就能驗。

## 軸標題的三個實作陷阱

這三條都是**讀 API 文件讀不到、只能實機撞上**的行為，記錄於此以免重蹈。

**一、`width: undefined` 才不會斷行。** recharts 的 `Label` 會把它算出的 viewBox
寬度往下傳給 `Text`，而 `Text` 只在**收到 `width` 時**才斷行：

```js
// recharts/es6/component/Text.js
if ((width || scaleToFit) && !Global.isSsr) { /* 斷行 */ }
```

Y 軸的 viewBox 寬度就是那條窄軸本身的寬度（數十 px），中文因此被折成一字一行。
此前兩度判定「旋轉後中文會斷行，與函式庫對抗不划算」而放棄軸標題——**那個歸因是
錯的，斷行與旋轉無關**，症結是這個繼承來的寬度。明確傳 `width: undefined` 即關閉
斷行。教訓：把一個可設定的參數誤判成函式庫的固有行為，代價是兩次放棄一個使用者
一眼就會期待的功能。

**二、標題傳 `label` 的物件形式，而非 `<Label>` 元素。** 兩者看似等價，但傳元素會
讓 recharts 走「先量測標題再決定軸尺寸」的分支（`XAxis.js` 的 `isValidElement(label)`），
該分支在 jsdom 下量到 0 而整個不渲染——測試一行都驗不到。物件形式由 recharts 自行
建構 `Label`，兩種環境行為一致。

**三、X 軸高度必須明給數字。** 標題以 `insideBottom` 排在軸自己的高度內（再以 `dy`
推離刻度），才不會被 SVG 下緣裁掉。而 `height="auto"` 只在標題是 React 元素時才量測
（承上，物件形式量不到），故明給 `X_AXIS_HEIGHT_WITH_LABEL`。

## 影響

**選填欄位的語意必須寫進 tool 描述。** 依 ADR 0003：選填欄位的說明只存在於巢狀
JSON Schema 的 property description 裡，LLM 未必讀得到。散佈圖的 tool 描述因此明文
要求為兩軸命名、有單位時另傳單位——若 LLM 從不主動使用，這次改動等於沒做。

**單位與大數值縮寫是兩條獨立路徑。** `tickFormatter`（我們的 K/M/B 縮寫）與 `unit`
（recharts 附加）各自運作，recharts 把後者接在前者的輸出之後。疊加後的實際輸出
（`1.2M件`）有測試守著——兩條路徑各自正確不保證疊起來正確。

**圖例可能遮住繪圖區角落的資料點。** 圖例排進繪圖區是知情的取捨。樣板圖實測為 0 個
資料點被遮，但最高點與圖例色塊僅差數 px——這個位置對「角落有資料點」的資料集仍屬
脆弱，留待實際案例出現時再處理。
