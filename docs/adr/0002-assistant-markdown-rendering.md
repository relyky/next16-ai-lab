# 助手回覆以 Streamdown 渲染 markdown

助手的回覆本來就是 markdown，先前卻以純文字呈現，字面符號直接露在畫面上——最難讀的是表格，`|---|---|` 與一堆豎線混在文字裡，一個本該一眼看懂的財務比較變成要用眼睛重新斷句。這與財務助手的用途直接衝突：它的回答天生充滿數字比較、分項列舉與計算過程，正是 markdown 結構最能幫上忙的地方。

選 `streamdown` 而非 `react-markdown`，理由是**串流**。回覆是逐字到達的，渲染器必須能處理未閉合的表格、程式碼圍欄與強調標記，並以區塊為單位記憶化，否則每個文字增量都會重繪整棵樹。`react-markdown` 兩件都不做。

## 被否決的替代方案

**用 `react-markdown` 加上「串流時顯示純文字、`done` 後才渲染」**。相依較輕，也避開了未完成 markdown 的所有難題。

否決的理由是**它把最有價值的那段體驗換掉了**。長回答的排版要等整段回完才出現，使用者盯著一大片裸符號等待——而回答愈長（愈需要排版幫忙）就等得愈久。這正好把好處讓給了最不需要的短回答。

次要理由是「切換」本身會露餡：純文字與渲染後的行高、間距、字重都不同，收尾時整塊內容會跳一下。要消掉這個跳動，得讓純文字階段預先模擬渲染後的排版——等於自己重寫一遍渲染器。

## Plugin 只裝三個

`cjk`、`code`、`math`，**刻意不裝 `mermaid`**。

`cjk` 是必需品而非裝飾。全站繁中，而一般 markdown 剖析器在 `**重點。**` 這種粗體標記緊貼全形句號的寫法下 emphasis 會失效，autolink 也會把尾隨的全形標點吃進連結。這兩件事在英文語境下不存在，用英文或半形標點都測不出來——這也是為什麼測試裡那一則必須寫成緊貼全形句號的形狀。

不裝 `mermaid` 的理由是本專案的圖表走另一條路：由 charts MCP tool 產生結構化圖表定義，交給 recharts 與圖表卡片渲染，不是 mermaid 語法。它同時是四者中最重的相依，且在 jsdom 下依賴瀏覽器 API 會拖累測試。日後真有需求再加。

## 提示訊息必須與回覆內容分離

中斷與失敗的提示原本是用換行**串接在回覆文字後面**，成為同一個字串。純文字模式下這無害；一旦改以 markdown 渲染就成了缺陷——若輸出停在未閉合的程式碼圍欄（串流中斷時極常見，使用者正是在助手吐程式碼吐到一半時按下中斷），後續的「（已中斷）」會被吞進程式碼區塊，變成灰底等寬字甚至整段不可見。**使用者按了中斷卻看不到已中斷。**

故提示改走訊息模型上的獨立欄位，以純文字渲染於 markdown 區塊之後。這是修缺陷，不是重構潔癖。

## 使用者訊息刻意不對稱

使用者泡泡維持保留換行的純文字，不走 markdown。使用者打字通常不是 markdown，渲染會把 `1. ` / `- ` / `#` 開頭的字面輸入吃掉變成清單或標題——那是幫倒忙。**這是刻意的不對稱，不是遺漏。**

## 影響

**接線有三處缺一不可**，且失敗樣態不同：

1. 引入 Streamdown 樣式表與 KaTeX 的 CSS。
2. 全域 CSS 的 `@source` 指令需指向 Streamdown 及各 plugin 的 dist，Tailwind v4 才會生成它們用到的 utility class。**路徑層數依全域 CSS 的實際位置而定**——本專案的 `globals.css` 在 `src/app/`，故為兩層 `../../node_modules/`，而非官方文件假設的一層。
3. **路徑寫錯不會報錯**，只會靜默渲染成完全無樣式的裸 HTML。畫面出現此症狀時，第一個檢查點就是它。dev 與 production 是不同的 CSS pipeline，兩邊都要確認。

**plugin 組態物件必須是模組層級常數。** 專案啟用了 React Compiler（`next.config.ts` 的 `reactCompiler: true`），而 Streamdown 是記憶化元件；每次 render 傳入新的物件字面量會使記憶化永遠失效，串流時每個增量都重繪整棵 markdown 樹——正是記憶化要擋的事。

**測試分兩個接縫。** markdown 渲染本身的斷言集中在元件層測試，對話頁整合測試只管串流與訊息流的行為，不因此長出大量 markdown 斷言。元件測試**不 mock 渲染器**：代價是 Shiki 首次載入語言與 KaTeX 會讓測試變慢，換來的是「表格真的渲染成表格」確實被驗證，而非驗證一個假的替身。

**斷言錨點與直覺不同。** Streamdown 的粗體不是 `<strong>` 而是 `<span data-streamdown="strong">`，連結不是 `<a>` 而是 `<button data-streamdown="link">`（它支援連結安全性攔截，故用可攔截的控制項）；斜體則是真正的 `<em>`。粗體與連結只能以 `data-streamdown` 這個對外標記斷言。

**串流動畫只能綁最後一則助手訊息。** 頁面的載入狀態是整頁層級的單一布林，直接傳給每一則訊息的話，串流期間所有歷史訊息都會收到「正在動畫」而重播淡入——使用者每問一個新問題，整段對話歷史就閃動一次。
